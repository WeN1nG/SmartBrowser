# AI 浏览器任务执行方案

## 1. 任务分解

接到用户任务后，拆分成若干可执行的子任务并按序执行，每完成一步汇报进度。

**例如**：去超星学习通完成计算机英语课程的所有作业

```
子任务1: 登录超星学习通平台           → 完成 ✓
子任务2: 找到计算机英语课程           → 完成 ✓  
子任务3: 找到该课程的所有作业列表     → 完成 ✓
子任务4: 逐个完成作业                 → 完成 ✓
子任务5: 确认所有作业通过             → 完成 ✓
子任务6: 汇报总结                     → 完成 ✓
```

## 2. 子任务执行规则

### 成功
- 子任务执行成功 → 汇报"当前工作已完成"，进入下一步

### 失败重试
- 首次失败 → 立即重试 1 次（可能只是页面抖动）
- 再次失败 → 换一种方法重试 2 次
  - 换选择器（hash → text → CSS）
  - 先 `browser_snapshot` 重新获取页面快照
  - `browser_wait_for` 等待片刻再操作
- 仍然失败 → 暂停任务，调用 `ask_user` 向用户求助
  - 说明已尝试的方法和现象
  - 请求用户指引

### 用户交互
- 需要用户提供信息/确认 → 调用 `ask_user` 暂停并等待
- 用户回答后自动恢复执行

## 3. 工具选择指南

| 场景 | 优先使用的工具 | 说明 |
|------|--------------|------|
| 打开页面 | `browser_navigate` | 自动等待加载完成 |
| 查看页面内容 | `browser_snapshot` | A11y 快照，比截图高效 |
| 点击元素 | `browser_click` | 用快照中的 `xp=` hash 定位 |
| 输入文本 | `browser_type` | 模拟真人打字，触发 key 事件 |
| 填充表单 | `browser_fill_form` | 多字段一次填充 |
| 下拉选择 | `browser_select_option` | 使用选项文本 |
| 搜索流程 | `compose_search` | 打开 Bing → 搜索 → 获取结果 |
| 提取数据 | `compose_extract` | 快照 + JS 提取结构化数据 |
| 多页采集 | `compose_paginate` | 循环翻页提取 |
| 视觉确认 | `browser_take_screenshot` | 最后一步视觉验证 |
| 按键操作 | `browser_press_key` | Enter, Tab, Escape 等 |
| 等待 | `browser_wait_for` | 等文本出现或固定延时 |

## 4. 核心原则

- **快照即事实**：`browser_snapshot` 返回什么就说什么，不编造页面内容
- **Hash 定位优先**：用 `xp=` hash 定位元素而非 CSS 选择器
- **及时总结**：提取到足够信息后立即给出答案，不再发起新工具调用
- **卡住就换路**：连续 3 次空结果说明方法行不通，换路线而非换参数
- **大胆求助**：尝试多种方法后仍无法推进，立即 `ask_user`
