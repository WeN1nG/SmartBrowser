# 修正_AI输出思考结论分区_6_9_12_00

focus ：修正 AI 对话框中 `[AI]` 输出混杂思考过程和最终答案的问题

reason : `Pro.md` 显示 AI 回复中混入了模型过程性文本，例如 `The user wants me...`、`Let me...`、`Now I need...`，以及 `上一步评估：`、`记忆：`、`下一目标：` 等执行过程内容，最终答案从「通过搜索结果来看...」才开始。原 UI 只有一个 `[AI]` 内容区，导致用户默认看到完整混杂内容。

deepreason : 当前渲染路径中 `ChatViewModel` 将所有流式 chunk 累积到 `ChatMessage.Content`，`AiChatPanel.xaml` 直接把 `Content` 绑定到一个 `FlowDocumentScrollViewer`。UI 没有区分过程性文本和最终结论；同时为兼容现有 API、会话保存和流式输出，不能直接改变 `Content` 的真实含义。

solution : 保留 `ChatMessage.Content` 作为完整原文，仅新增 UI-only 派生分区：
- `ThinkingContent`：思考过程，默认折叠显示。
- `ConclusionContent`：最终结论，始终可见。
新增 `AssistantResponseParser` 根据显式标记和保守启发式拆分内容；`AiChatPanel.xaml` 对 Assistant 消息使用分区模板，把原来的单块 `[AI]` 输出改为 `[思考过程]` + `[结论]`。

```csharp
public static AssistantResponseSections Parse(string content)
{
    if (string.IsNullOrWhiteSpace(content))
        return new AssistantResponseSections(string.Empty, string.Empty);

    var explicitSections = ParseExplicitSections(content);
    if (explicitSections.HasValue)
        return explicitSections.Value;

    var splitIndex = FindHeuristicConclusionStart(content);
    if (splitIndex <= 0 || splitIndex >= content.Length)
        return new AssistantResponseSections(string.Empty, content.TrimStart());

    var thinking = content[..splitIndex].Trim();
    var conclusion = content[splitIndex..].TrimStart();
    if (thinking.Length < 20 || conclusion.Length < 5 || !HasThinkingCue(thinking))
        return new AssistantResponseSections(string.Empty, content.TrimStart());

    return new AssistantResponseSections(thinking, conclusion);
}
```
