# 修正指南

## 修正_AI任务清单右侧布局与稳定性_6_7

### focus
完成 Pro.md 中针对 AI 模块的 5 项要求：修复最后一次使用后未响应/崩溃风险、将 todolist 移到 AI 模块右侧并扩大显示区域、确保 todolist 是任务拆分阶段一次性设计的完整子任务列表、让 AI 最新输出始终保持在底部可见，并同步更新 Help 文档。

### reason
此前 AI 面板将实时任务清单插在消息列表上方，并限制 `MaxHeight=150`，复杂任务的子任务较多时显示区域不足，还会挤压消息输出区域。消息列表只在 `Messages.CollectionChanged` 时滚动到底部，流式输出期间只触发单条消息 `Content` 变更，最新输出不一定保持可见。`AiChatPanel` 在每次 Loaded 时追加事件订阅但没有 Unloaded 解除，副窗口多次显示/隐藏后可能重复订阅，造成额外 UI 调度和未响应风险。

### deepreason
1. Todo UI 位于主 Grid 行布局中，占用纵向空间，不满足“放到 AI 模块右方”的布局要求。
2. AI 输出是流式追加到同一个 `ChatMessage.Content`，集合本身没有新增项时不会触发原有自动滚动。
3. Markdown 转换器对完整历史输出反复转换，长回复流式更新时会增加 UI 线程压力。
4. `update_todo` 的工具说明虽然要求传完整列表，但系统提示与工具参数没有明确“首次必须一次性写入全部子任务、后续仅更新状态”。
5. 新建/清空/加载对话时若上一次 ask_user 或流式请求仍有挂起状态，需要同步清理等待状态，避免最后一次使用后残留状态影响下一次操作。

### solution
- 将 `AiChatPanel.xaml` 主内容改为左右两栏：左侧最近对话 + 消息输出，右侧固定任务清单栏。
- 将 `AiSecondaryWindow` 默认宽度从 340 扩到 720，并提高可调整宽度上限，为右侧任务清单提供足够区域。
- `AiChatPanel.xaml.cs` 增加 ViewModel/消息事件的 Attach/Detach，避免重复订阅；同时监听 `ChatMessage.Content` 变化，在流式输出期间也自动滚动到底部。
- `MarkdownToFlowDocumentConverter` 对超长消息只渲染最新 12000 字符，降低流式长输出导致 UI 卡顿的概率。
- `ContextBuilder` 与 `update_todo` 工具说明明确要求：首次调用一次性建立完整子任务列表，后续实时更新只更新既有子任务状态。
- `ChatViewModel` 在新请求、新建、清空、加载对话时取消旧请求并清理 ask_user 等挂起状态；`start_subtask` 若收到未预登记子任务，会记录警告，帮助定位 AI “做一个写一个”的违规行为。

### keychangecode

```csharp
// AiChatPanel.xaml.cs: 消息内容变化也触发滚动
private void OnMessagePropertyChanged(object? sender, PropertyChangedEventArgs e)
{
    if (e.PropertyName == nameof(ChatMessage.Content))
        ScrollToBottom();
}

private void ScrollToBottom()
{
    if (_isAutoScrolling) return;
    _isAutoScrolling = true;

    Dispatcher.BeginInvoke(() =>
    {
        try { MessageScroller?.ScrollToBottom(); }
        finally { _isAutoScrolling = false; }
    }, DispatcherPriority.ContextIdle);
}
```
