# 修正_规划门禁API报错_6_9_00_35

focus ：修正 AI 任务清单规划门禁启用后出现 API 报错的问题

reason : 最新日志显示两类错误：
- `deepseek-v4-flash` 在首轮强制 `tool_choice=update_todo` 时返回 `BadRequest: Thinking mode does not support this tool_choice`。
- 切换到火山方舟 Coding Plan 后，配置仍被运行时识别为 `provider=anthropic`，导致请求走 Anthropic 原生 `/v1/messages` 协议和 `x-api-key` 认证，实际 endpoint 却是 OpenAI 兼容的 `https://ark.cn-beijing.volces.com/api/coding/v3`，因此任务循环返回 `Unauthorized`。

 deepreason : 之前的连接测试只发送普通 OpenAI 兼容请求，不携带工具强制参数，所以能够成功；但正式工具循环新增规划门禁后，会根据 provider 选择请求协议并注入 `tool_choice`。DeepSeek/Thinking 模式不兼容强制 `tool_choice`；同时历史/运行时配置中存在 `anthropic + ark endpoint` 的协议错配，导致测试连接和工具循环使用的协议不一致。

solution :
1. 对 OpenAI 兼容请求增加强制 `tool_choice` 兼容判断：DeepSeek 与 thinking/reasoning 模型不再发送 `tool_choice` 字段，改注入系统提醒要求当前轮先调用规划工具。
2. 对 provider/endpoint 错配做持久化和运行时兜底修正：`anthropic` 配置若指向 OpenAI 兼容端点，自动改为 `volcengine-ark` 或 `custom`，从而使用 Bearer 和 `/chat/completions`。
3. OpenAI 兼容端点统一通过 `GetOpenAIChatCompletionsEndpoint()` 补齐 `/chat/completions`，支持填写 Base URL。
4. 连接测试失败时记录服务商返回的错误摘要，便于后续定位。

```csharp
private bool SupportsForcedToolChoice(ProviderInfo? provider)
{
    if (provider?.Key is "deepseek")
        return false;

    var model = Settings.Model ?? string.Empty;
    if (model.Contains("reason", StringComparison.OrdinalIgnoreCase)
        || model.Contains("thinking", StringComparison.OrdinalIgnoreCase))
        return false;

    return true;
}
```

```csharp
private static void NormalizeProviderProtocol(AiSettings settings)
{
    if (settings.ProviderKey != "anthropic" || !LooksLikeOpenAICompatibleEndpoint(settings.ResolvedEndpoint))
        return;

    Logger.Warning($"AI 配置协议自动修正: provider=anthropic, endpoint={settings.ResolvedEndpoint} → OpenAI 兼容协议");
    settings.ProviderKey = settings.ResolvedEndpoint.Contains("ark.cn-beijing.volces.com", StringComparison.OrdinalIgnoreCase)
        ? "volcengine-ark"
        : "custom";
}
```
