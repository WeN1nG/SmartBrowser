# 修正_AI待办任务清单为空_6_9_00_00

focus ：修正 AI 待办任务清单为空、AI 未先进行任务分解的问题

reason : 最新日志显示 `update_todo` 已注册，但用户请求「什么是 tyloo」后的工具循环首轮直接调用 `browser_navigate`，之后继续 `observe_browser` / `browser_click` / `browser_js`，整个会话没有调用 `update_todo` 或 `start_subtask`，所以右侧待办任务清单一直为空。

deepreason : 旧逻辑只在系统提示词与工具描述中要求 AI 先拆分任务，但没有在 API 请求层强制规划工具。部分模型会忽略软提示，直接使用浏览器工具执行任务；同时 `update_todo` 接收空 items 时会清空 UI，`start_subtask` 遇到未预登记子任务时会自动新增，无法保证“一次性完整拆分”。

solution : 在 `AiClient` 构造 OpenAI/Anthropic 请求时加入规划门禁：工具循环首轮强制 `tool_choice=update_todo`，任务清单建立后但第一个子任务尚未开始时强制 `tool_choice=start_subtask`。同时强化 `update_todo` 与 `start_subtask` 的参数校验，拒绝空清单和未预登记子任务，并更新系统提示/工具描述/调试文档。

change :
- `Demo/BrowserDemo/Services/AiClient.cs`：新增 `ResolveRequiredPlanningTool(List<ChatMessage>)`；在 OpenAI/Anthropic 请求构造中根据对话状态设置 `tool_choice`。
- `Demo/BrowserDemo/ViewModels/ChatViewModel.cs`：`update_todo` 拒绝空 items；`start_subtask` 未找到预登记 id 时返回错误；更新工具描述。

- `Help/FunctionHelp.md`：记录新增/变更函数行为。

```csharp
private string? ResolveRequiredPlanningTool(List<ChatMessage> messages)
{
    if (ContextBuilder is not { IsEnabled: true, RegisteredTools.Count: > 0 })
        return null;

    var hasUpdateTodo = ContextBuilder.RegisteredTools.Any(t => t.Name == "update_todo");
    var hasStartSubtask = ContextBuilder.RegisteredTools.Any(t => t.Name == "start_subtask");
    if (!hasUpdateTodo)
        return null;

    var hasToolResult = messages.Any(m => m.Role == MessageRole.Tool);
    if (!hasToolResult)
        return "update_todo";

    var hasTodoCreated = messages.Any(m =>
        m.Role == MessageRole.Tool &&
        string.Equals(m.ToolName, "update_todo", StringComparison.OrdinalIgnoreCase));
    if (!hasTodoCreated)
        return "update_todo";

    var hasSubtaskStarted = messages.Any(m =>
        m.Role == MessageRole.Tool &&
        string.Equals(m.ToolName, "start_subtask", StringComparison.OrdinalIgnoreCase));
    if (hasStartSubtask && !hasSubtaskStarted)
        return "start_subtask";

    return null;
}
```
