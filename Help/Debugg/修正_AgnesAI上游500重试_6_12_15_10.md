# 修正_AgnesAI上游500重试_6_12_15_10

focus ：解决自定义 AgnesAI/OpenAI 兼容提供商返回 `InternalServerError / do_request_failed` 时工具循环直接中断的问题

reason : 最新日志 `Demo/BrowserDemo/Log/6-12-14-49-59.log` 显示：
- 当前配置：`provider=custom`, `model=agnes-2.0-flash`
- 第 1 轮请求成功，AI 调用了 `update_todo`
- 第 2 轮请求在回传工具结果后立刻失败：

```text
API 请求失败: InternalServerError — {"error":{"message":"upstream error: do request failed (request id: 20260612065043525293959aYB8FXzD)","type":"AgnesAI_error","param":"","code":"do_request_failed"}}
```

deepreason : 这不是浏览器自动化或工具 schema 错误；第 1 轮 SSE 和 tool call 均已正常完成。错误来自自定义提供商网关/上游模型调用层的瞬时 500。旧代码只对 429 做退避重试，遇到这种 `upstream error` / `do_request_failed` 直接返回错误，导致任务中断。另外旧 429 重试路径复用同一个 `HttpRequestMessage`，在 .NET 中请求内容发送后不应复用，重试时需要重新构造请求。

solution : 抽取统一的 `RetryTransientFailureAsync`：
- 继续对 429/TooManyRequests 做指数退避重试。
- 对 500/502/503/504 且错误体包含 `upstream error`、`do_request_failed`、`overloaded`、`temporarily` 的上游瞬时错误做指数退避重试。
- 每次重试都通过 `requestFactory` 重新构造新的 `HttpRequestMessage`，避免复用已发送请求。
- 普通 4xx 或非瞬时错误仍立即返回给用户。

change :
- `Demo/BrowserDemo/Services/AiClient.cs`
  - 新增 `MaxTransientErrorRetries` / `TransientErrorBaseDelayMs`。
  - `StreamMessageAsync` 和工具循环用的 `StreamRichEventsAsync` 都改为通过 `requestFactory` 构造请求。
  - 新增 `RetryTransientFailureAsync` 和 `IsRetryableApiFailure`，统一处理 429 与上游瞬时 5xx。
