# 修正指南

## 修正_六项Bug修复_6_5_23_00

### focus
修复日志中发现的6个问题：假成功、导航不检查失败、wait立即返回、窗口定位风暴、标签切换上下文滞后、缺少ask_user暂停机制

### reason
从日志 6-5-21-39-57.log 中分析发现以下问题：
1. **假成功**：JS 返回 `{"error":"元素未找到"}` 但代码仍报告 `✅ 成功 — ✅ 已输入文本`（影响 AI 决策正确性）
2. **导航不检查失败**：导航到 404 页面 `WebError=Unknown` 但报告 `✅ 成功 — 已导航到...`
3. **Wait 0ms**：`skill_wait` 调用后总是立即返回 `0ms`（影响较小，导航已完成时才正确）
4. **窗口定位 CPU 风暴**：`PositionNextToMainWindow` 在 240ms 内调用 60+ 次
5. **标签切换上下文滞后**：AI 在新标签页操作时仍使用旧标签页的 URL/Title
6. **缺少 ask_user 暂停机制**：AI 无法在关键决策点向用户求助，浪费 8 轮工具调用

### deepreason
1. WebView2AutomationBridge 的 JS 注入方法未检查执行结果中的 error 字段
2. ExecuteNavigate 只等待 500ms 就返回，不等待实际导航完成
3. 窗口事件绑定没有防抖处理
4. 标签切换时未同步 ChatViewModel 上下文
5. ask_user 的完整"暂停→等待用户→恢复"架构设计已在 DESIGN.md 中但代码未实现

### solution
**Bug 1 (P0)**：WebView2AutomationBridge 新增 `GetJsError()` 辅助方法，所有 JS 注入方法执行后先检查 error
**Bug 3 (P0)**：ExecuteNavigate 改为轮询 document.readyState（最长15s），检查页面标题/内容错误关键词
**Bug 4 (P1)**：OnMainWindowLocationChanged/SizeChanged 改为 `DebouncePositionWindow()`，100ms 防抖
**Bug 5 (P1)**：OnTabActivated 中新增 URL/Title 同步到 _vm.Chat
**Bug 6 (P2)**：完整实现 ask_user 机制：
  - ChatViewModel: 注册 ask_user 工具、ExecuteAiToolAsync 检测、RespondToQuestionAsync 恢复
  - AiClient: ExecuteToolWithErrorHandlingAsync 分离、__ASK_USER_PAUSED__ 标记检测
  - AiChatPanel.xaml: 问题卡片 UI（confirmation/multiple_choice 模式）
