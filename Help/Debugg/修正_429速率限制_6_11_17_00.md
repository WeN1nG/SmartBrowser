focus ： 解决 API 调用 TooManyRequests (429) 导致工具循环中断的问题
reason : 工具循环中 AI 快速连续发起 API 请求，触发了自定义（AgnesAI）提供商的免费套餐速率限制，在第 21 轮迭代时被强制中断。
deepreason : StreamRichEventsAsync 在收到 429/TooManyRequests 响应时直接报错并 yield break，没有任何重试或退避机制。同时工具循环中相邻迭代之间无延迟，请求间隔仅数毫秒。
solution : 在 StreamRichEventsAsync 中为 429/TooManyRequests 添加指数退避重试（最多 3 次，基础延迟 2000ms，翻倍递增：2s → 4s → 8s）。非 429 错误行为不变。

change : Demo/BrowserDemo/Services/AiClient.cs Line 18-22 (新增常量), Line 1023-1075 (429 重试逻辑)
keychangecode :
```csharp
// 新增常量 (Line 18-22)
private const int MaxRateLimitRetries = 3;
private const int RateLimitBaseDelayMs = 2000;

// 429 重试逻辑 (在 IsSuccessStatusCode 检查内)
if (response.StatusCode is TooManyRequests || response.StatusCode == (HttpStatusCode)429)
{
    // 循环重试 3 次，每次延迟翻倍 (2s, 4s, 8s)
    for (int attempt = 1; attempt <= MaxRateLimitRetries; attempt++)
    {
        await Task.Delay(RateLimitBaseDelayMs * (int)Math.Pow(2, attempt - 1), ct);
        response = await _http.SendAsync(request, ...);
        if (response.IsSuccessStatusCode) break;
        // 非 429 错误直接报错
    }
}
```
