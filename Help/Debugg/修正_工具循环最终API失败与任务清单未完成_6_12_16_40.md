focus ：修正工具循环已完成用户任务后，最后继续请求触发 API 请求失败，并且右侧任务清单未在最终结果后全部更新的问题

reason : 最新日志 `Demo/BrowserDemo/Log/6-12-15-57-22.log` 显示 AI 已经读取并总结 QQ 邮箱重要未读邮件，但工具循环仍继续请求到第 100+ 轮；在上下文压缩后请求体仍过大，最终触发 `ContextWindowExceededError`，UI 把它追加成 `⚠️ API 请求失败`。同时日志中只有 `update_todo` / `start_subtask`，没有最后的 `finish_subtask` 或完整 `update_todo`，所以任务清单停留在进行中。

deepreason : `AiClient.ExecuteConversationAsync` 对所有 API 非成功响应都以 error 事件返回给 UI，即使错误是“上下文窗口已满”这种发生在任务已产出有效总结之后的停止条件；而 `ChatViewModel.SendAsync` 只相信模型主动调用 `finish_subtask` / `update_todo` 来收尾，缺少最终文本回复后的任务清单兜底同步。

solution : 
- 在 `StreamRichEventsAsync` 中识别 `ContextWindowExceeded` / `maximum context length` / `max context`，记录 warning 后直接结束当前工具循环，不再向用户回复追加 API 请求失败文本。
- 在工具循环正常结束、最终回复清洗后调用 `TryFinalizeTodoAfterAssistantReply`，当右侧任务清单存在、没有 blocked 项且最终回复看起来已经给出结果时，将未完成项兜底标为 `completed`，并清空 `RuntimeActiveSubtaskId`。
