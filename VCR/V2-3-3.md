## 3. 详细变更分析

### 3.1 快照引擎全面升级（AutomationScripts.cs）

**变更文件**：`Demo/BrowserDemo/Services/Automation/AutomationScripts.cs`

#### 3.1.1 Paint Order 遮挡标记（P1）

**新增 JS 函数**：

```javascript
// paintOrder: 返回元素的 zIndex 数值，auto 记为 0
paintOrder: function(el) {
    var cs = el.getRootNode().getComputedStyle(el);
    return parseInt(cs.zIndex) || 0;
}

// detectOverlaps: 批量检测元素间遮挡关系
detectOverlaps: function(elements) {
    for (var i = 0; i < elements.length; i++) {
        for (var j = 0; j < elements.length; j++) {
            if (i === j) continue;
            if (elements[j].paintOrder > elements[i].paintOrder &&
                rectsOverlap(elements[j].viewportRect, elements[i].viewportRect)) {
                elements[i].overlapped = true;
                break;
            }
        }
    }
    // 清理内部字段
    elements.forEach(function(e) { delete e.viewportRect; });
    return elements;
}
```

**设计决策**：采用**标记而非删除**策略——给可能被遮挡的元素设置 `overlapped: true`，让 AI 自行判断是否跳过，而不是直接剔除。

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `paintOrder` | integer | 元素 zIndex 值，auto 记为 0 |
| `overlapped` | boolean | 是否被更高 zIndex 元素遮挡 |
| `viewportRect` | object | 内部字段 `{x, y, width, height}`，处理后清理 |

#### 3.1.2 Stable Hash 稳定元素匹配（P1）

**新增 JS 函数**：

```javascript
function stableHash(el) {
    var parts = [
        el.tagName.toLowerCase(),
        el.getAttribute('aria-label') || '',
        el.getAttribute('name') || '',
        el.getAttribute('placeholder') || '',
        (el.textContent || '').trim().substring(0, 50),
        el.getAttribute('type') || ''
    ];
    var key = parts.filter(function(p) { return p.length > 0; }).join('|');
    return simpleHash(key);
}
```

- 使用 djb2 算法计算 36 进制 hash（如 `a1b2c3`）
- 基于 tag + aria-label + name + placeholder + text + type 复合计算
- 页面刷新/DOM 重建后 stable_hash 保持不变，支持跨 snapshot 元素追踪
- 每个元素约增加 ~8 字节

**冲突处理**：在 `ClickByStableHashAsync` 中检测到多个匹配时返回 `"multiple_matches"` 警告。

#### 3.1.3 复合控件内联提取（P1）

**新增字段**（在 `collectElementInfo` 中）：

```javascript
if (el.tagName === 'SELECT' && el.options.length > 0) {
    var labels = [];
    for (var i = 0; i < el.options.length; i++) {
        labels.push(el.options[i].text + '(' + el.options[i].value + ')');
    }
    info.inline_options = labels.join('  ');
}
```

**输出示例**：

```json
{
    "id": 5,
    "tag": "select",
    "aria_label": "国家",
    "inline_options": "中国(CN)  美国(US)  日本(JP)"
}
```

**支持的控件类型**：

| 控件 | 新增字段 | 说明 |
|------|---------|------|
| `<select>` | `inline_options` | 所有选项的 `文本(值)` 列表 |
| `<input type="date">` | `format_hint` / `min` / `max` | 格式提示 `YYYY-MM-DD`，范围边界 |
| `<input type="range">` | `range_desc` | `min=X, max=Y, value=Z` |
| `<input type="color">` | `color_desc` | `当前: #xxxxxx` |

#### 3.1.4 Viewport Center 坐标点击基础（P4 → 提升为 P0）

**新增字段**：

```javascript
viewportCenter: function(el) {
    var rect = el.getBoundingClientRect();
    return {
        x: Math.round(rect.left + rect.width / 2),
        y: Math.round(rect.top + rect.height / 2)
    };
}
```

返回元素中心点相对于视口左上角的坐标，用于 `browser_click_at(x, y)` 兜底点击。每个元素约 +20 字节，100 个元素约 +2KB。

#### 3.1.5 DOM Text Hash 页面停滞检测（P0）

**新增 JS 函数**：

```javascript
getDomTextHash: function() {
    var body = document.body;
    if (!body) return '0';
    
    var walker = document.createTreeWalker(body, NodeFilter.SHOW_TEXT, {
        acceptNode: function(node) {
            var parent = node.parentElement;
            if (!parent) return NodeFilter.FILTER_REJECT;
            var tag = parent.tagName.toLowerCase();
            if (tag === 'script' || tag === 'style' || tag === 'noscript') 
                return NodeFilter.FILTER_REJECT;
            var cs = parent.getComputedStyle();
            if (cs.display === 'none' || cs.visibility === 'hidden') 
                return NodeFilter.FILTER_REJECT;
            return NodeFilter.FILTER_ACCEPT;
        }
    });
    
    var textParts = [];
    var node;
    while (node = walker.nextNode()) {
        var t = node.textContent.trim();
        if (t.length > 0) textParts.push(t);
    }
    
    var fullText = textParts.join(' ');
    return simpleHash(fullText);
}
```

- 使用 TreeWalker 遍历所有可见文本节点
- 排除 script/style/隐藏元素的文本
- 返回 djb2 hash（36 进制字符串）
- 在 `browser_snapshot` / `observe_browser` 后由 `AiClient` 调用 `RecordDomTextHash()`

#### 3.1.6 Type 输入值验证增强（P2）

**`typeInElement` 函数增强**（JS 层）：

```javascript
typeInElement: function(id, text, clearFirst) {
    var el = this.getElementById(id);
    if (!el) return { success: false, error: 'element_not_found' };
    
    // ... 原有输入逻辑 ...
    
    // 验证最终值
    var finalValue = el.value;
    return {
        success: true,
        expected: text,
        actual: finalValue,
        mismatch: text !== finalValue
    };
}
```

当 `mismatch: true` 时，AI 可知晓输入值被框架（Vue/React/日期格式化等）修改。

#### 3.1.7 变更汇总

| 配置项 | 旧值 | 新值 | 说明 |
|--------|------|------|------|
| 快照元素字段 | id, tag, text, role, type, name, href, aria_label, placeholder, value | **+paintOrder, overlapped, stable_hash, viewport_center, inline_options/format_hint/range_desc/color_desc** | 新增 6 个字段家族 |
| typeInElement 返回 | success, element_id | **+expected, actual, mismatch** | 值验证 |
| getSnapshot 返回 | 元素数组 | **+getDomTextHash()** | 页面停滞检测 |

### 3.5 ContextBuilder 结构化思考框架

**变更文件**：`Demo/BrowserDemo/Services/ContextBuilder.cs`

#### 3.5.1 AppendOutputFormat 增强

在系统提示词的"输出格式要求"章节中强制 AI 输出四个结构化字段：

```
每次回复必须按以下格式输出：

[上步评估] 简要评价上一步操作的执行结果和目标达成情况。
  - 操作：做了什么（哪个工具，对哪个元素）
  - 结果：成功/失败/部分成功
  - 问题：是否有异常或需要调整的地方

[进度记忆] 记录当前任务进度。
  - 已完成：已经完成了哪些子任务/步骤
  - 进行中：当前正在执行哪一步
  - 待完成：还有哪些步骤需要做

[下步目标] 明确下一步要做什么，以及为什么。
  - 目标：下一步的具体操作
  - 依据：基于什么判断需要做这一步

[结论]
  工具调用 1: {"name": "browser_click", "arguments": {"element_id": 5}}
  或直接输出文本（如果是最终回答）
```

**要求**：每个字段都必须填写，`[上步评估]` 必须引用具体工具调用结果，`[进度记忆]` 必须与 TaskStateMachine 子任务状态一致。

#### 3.5.2 系统提示词 XML 分段决策

**决策**：未采用 BrowserUse 计划中的 XML 标签分段（`<system_identity>`, `<browser_state>` 等），继续使用 Markdown 格式。理由是现有 Markdown 格式已能清晰分隔各信息块，XML 标签会增加系统提示词长度而对中文 LLM 的理解帮助有限。

## 4. 影响与风险评估

### 4.1 破坏性变更

| 变更类型 | 影响范围 | 说明 |
|---------|---------|------|
| **快照字段膨胀** | `browser_snapshot` / `observe_browser` | 每个元素新增 paintOrder, overlapped, stable_hash, viewport_center, inline_options 等字段，平均增加 ~50-80 字节/元素 |
| **新工具注册** | `BrowserAutomationToolRouter` | 新增 3 个工具定义（click_at, click_by_hash, scroll_to_element），AI 可能尝试调用 |
| **自检测新维度** | `AgentEventSelfHandler` | DOM hash / 失败计数 / 探索限制新增 3 种检测，可能导致更早的终止 |
| **预算警告注入** | 所有工具循环 | 在 40/60/72/76 轮注入系统消息，改变 AI 收到的上下文 |
| **结构化思考强制** | AI 回复格式 | 系统提示词要求 `[上步评估]`/`[进度记忆]`/`[下步目标]`，AI 可能因格式约束降低灵活性 |

### 4.2 向后兼容性

**兼容策略**：
- 新增快照字段为**增量添加**，不修改现有字段结构
- `overlapped` 标记为保守策略（默认 false），不会误删元素
- `stable_hash` 为辅助定位手段，不影响现有 `element_id` 点击流程
- DOM hash 检测对动态页面（时钟、动画）可能敏感，阈值设为 4 次终止以降低误判
- 预算警告仅为提示信息，不影响工具循环正常结束

## 5. 总结

本次变更是从 BrowserUse 学习借鉴的**大规模功能扩展**，核心围绕三个方向：

**1. DOM 理解增强** — 快照引擎从"可见性过滤"升级为"视觉保真"：
- `paint_order` + `overlapped` 标记被高 z-index 元素遮挡的节点
- `stable_hash` 实现跨 snapshot 元素追踪，解决 SPA/AJAX 后 element_id 失效问题
- `inline_options` 展开复合控件选项，消除 AI 猜测
- `viewport_center` 为坐标点击兜底提供基础

**2. 元素交互扩展** — 减少对 `element_id` 的单一依赖：
- `browser_click_at(x, y)` 坐标点击兜底
- `browser_click_by_hash(stable_hash)` 稳定哈希点击
- `browser_scroll_to_element(element_id)` 精准定位
- `browser_type` 增强值验证（expected vs actual）

**3. 自检测深化** — 从"工具重复检测"扩展到"页面状态检测"：
- DOM text hash 页面停滞检测（2 次告警 / 4 次终止）
- 连续失败 replan 检测（3 步引导重新规划）
- 探索步数限制（5 步游离提醒）
- 预算渐进警告（50/75/90/95% 提醒）

同时延续了 V2-3-2 的**中断恢复能力**（`RecoverFromInterruption`、`ForceRestart`、`AllTasksBlocked` 重启），形成了完整的"规划→执行→检测→恢复"闭环。

**落地率**：22 项改进中 17 项已实施（77%），5 项因复杂度/成本/必要性考量暂未实施。

**风险等级**：🟠 **中高** — 快照字段膨胀增加上下文压力，新增自检测维度可能更早触发终止，新工具扩展了 AI 的操作空间但也增加了不确定性。

**建议优先级**：
1. 🔥 **P0**：DOM hash 停滞检测的误判率验证（特别是动态页面）
2. 🔥 **P0**：`stable_hash` 冲突率测试（多元素同名/同标签场景）
3. ⚠️ **P1**：`browser_click_at` 坐标点击的可靠性测试（不同 DPI/缩放比例）
4. ⚠️ **P1**：快照字段膨胀后的上下文压缩效果验证
5. ℹ️ **P2**：`replan_task` 工具和 `ProcessRuntimeReplan` 状态机方法的后续实施
